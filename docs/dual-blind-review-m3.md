## 二、双重比对与终局裁定

**P0×2（X 组双席共中，最高置信，同根因）——裁定成立，M3 附条件不通过**：
1. **并发下单事务完整性破缺**：两路并发 POST /orders（即使异商品无冲突）→双 500+非确定性半提交（订单落库而客户端收错）
2. **事务悬挂→全站幽灵写**：并发后连接陷入未决事务，此后 API 报成功但外部不落库、写锁被持有、verify 端点对幽灵链报 valid=true（脑裂）——**审计期间活库中招，协调席已重启恢复+清残余（商品440-445/订单19-23）**
- 根因（两席一致）：TypeORM sqlite 单共享连接上并发 `manager.transaction()` 交叉 BEGIN/ROLLBACK——AuditService 注释自认此雷且只给链建了串行队列，订单事务未纳入

**P1 修复清单**：
1. 全局写事务互斥（P0 根治）：chainTail 串行队列思想推广为共享写互斥，orders/products/audit 三域写事务全部纳入；修后并发下单应为 201+201 或 201+409（乐观锁语义化），绝不 500/半提交
2. orders create 补 isActive 过滤（下架品直购 201→400"商品已下架"）——X 组共中
3. verify --json 退出码透传（锚不符 json=0 → 2）——X1
4. verify --anchor 先判 MISMATCH 拒追加+锚文件同 seq 异哈希体检——Y1
5. verify 在 git 仓库内检查锚文件未 commit 改动（git diff --quiet）+区分损坏/不存在——X2/Y2 共中
6. F7 build 产物视觉验收补做（三档 Playwright 抽查留证）——Y 组共中
7. 锚窗口无界入已知限制声明（锚后增删机器不可检，如实）——X 组共中

**P2 记账**：audit verify 端点全表读无界（规模挂账）/商品图 404 无 onerror/audit 永久增长代价入 BACKLOG/审计链测试增量噪音（诚实链史留存）
