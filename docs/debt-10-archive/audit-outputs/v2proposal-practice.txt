## 1. DDL 可执行性实测

**1a. sqlite 真跑——通过**。§3.2 的 17 列 DDL + 3 索引在 sqlite 一次执行通过；判据 2 / 判据 4 的 SQL 建表后均可跑；`idx_domain_events_relay` 被 `WHERE relay_state='PENDING' ORDER BY id` 扫描谓词实际命中（EXPLAIN QUERY PLAN 证实）；多个 PENDING 行（seq=NULL）在 `idx_domain_events_seq` 唯一索引下合法共存（sqlite/MySQL 语义均允许多 NULL）。DDL 本体可执行。

**1b. TiDB 注释分支与仓内先例——[P1]**。v2 只给了注释分支（`-- TiDB: BIGINT AUTO_INCREMENT PRIMARY KEY`），而它自称沿用的先例 `backend\src\database\migrations\20261011000001-create-order-snapshots-table.ts` 是真双分支（information_schema/sqlite_master 探测 + 幂等）。更要害的是**先例自身的方言判定在 TiDB 上是错的**：先例用 `SELECT @@version` 后 `includes('mysql')||includes('mariadb')` 判 MySQL 系，而 TiDB 版本串格式为 `8.0.11-TiDB-v…`（PingCap 官方文档），两个子串都不含 → 在 TiDB 上误走 SQLite 分支 → sqlite_master 查询失败被 catch 吞掉 → 拿双引号标识符的 SQLite 方言 DDL 在 TiDB 默认 sql_mode（无 ANSI_QUOTES）下执行必炸。该雷从未暴露，因为 DatabaseModule 从未挂载、TiDB 冒烟从未跑过（见 §6）。v2 引此先例为双方言模板 = 把未爆雷写进规范。判据 1 的"或 MySQL 兼容库"逃生口（§4.2.1）恰好测不出这一点——普通 MySQL 的版本串含 'mysql'，检测分支走对。

**1c. DDL 与白名单投影的关系——[P2]**。"白名单投影（P1 schema 的组成部分——建表即有）"表述错位：投影是应用层函数，schema 里不存在任何强制它的东西；§4.1 P1 行确实列了"白名单投影函数"为交付件（工件不缺），但落点未给：函数住哪个模块、类 1（事务内 INSERT）与类 2（worker 侧）两条写腿如何被强制经投影、schema 层无约束时谁防裸 payload 直写、per-event_type 白名单枚举（"D 员六要素+资源标识为必要集"只是必要集定义，不是枚举表）均无。判据 4 只能事后烟测，不能事前防。

**1d. 列名约定断裂——[P2]**。DDL 用 snake_case（`schema_version`/`event_type`），而 §3.3 canonical 键序是 camelCase，且仓内两条既有链的列名全是 camelCase（audit_logs：createTime/userId…；order_snapshots 迁移："orderId"/"operatorType"…），链核 `audit-chain.ts` 的 canonicalizeRow 是**按 canonical 键名直读 row 字段**（无映射层）。domain_events 若按 §3.2 落 snake_case 列，就引入一条此前不存在的列名↔键名映射层——对一个"开局冻结键序、字节精确即链"的承重件，这是新增失败面。

**1e. dev=synchronize 现实被略过——[P2]**。先例注释明说 dev 走 `synchronize=true` 自动建表、迁移是 prod（synchronize=false）件；即 §3.2 DDL 实际是 prod 工件，dev 真源是一个尚不存在的 TypeORM entity 文件，先例的"与 entity 逐项对齐"纪律 v2 只字未提。照 §3.2 单独实施会造出 dev/prod schema 漂移面。

- **计数错误 [P3]**：§1.2 与 §3.7 两处均称"9 条"，但给出的区间 W4-W6（3 条）+ W8-W12（5 条）= **8 条**。以本仓数字纪律口径，承重计数与自给区间不符。

  - **W12 [P1]**：`createRefund`（payment-application.service.ts:371-449）在域变更与 save 之间夹着**外部网关调用**（:413 gateway.createRefund，网络往返）。事务化只有两条路：把整个流程包进 runExclusiveWrite+BEGIN = 进程级全局写互斥横跨网络 I/O（回调延迟期间 orders/audit/products 全部写排队）；或重构时序（先落 intent 事务、网关调用移到 commit 后）= 改域守卫流语义。v2 一行"事务底座改造+类 1 事件"带过。
