## 一、规格 g（NEEDS_REVIEW）状态机闭环推演

**迁移图核对**（据 §2 规格 g + §3.9）：PENDING_GATEWAY →{成功/拒绝（规格 h 裁决）}→ CONFIRMED/FAILED；PENDING_GATEWAY →{attempts 达线}→ NEEDS_REVIEW；NEEDS_REVIEW →{人工三出口}→ CONFIRMED / FAILED / PENDING_GATEWAY（attempts 清零）。CONFIRMED/FAILED 无出边（终态成立）。守卫计入集={PENDING_GATEWAY, NEEDS_REVIEW, CONFIRMED}，排除集={FAILED}——规格 b（v4）+规格 g 两句合成后闭合。以下为各推演缺口。

**[L5-01｜P1] §3.9 定义句“五态”与同句枚举 4 态自相矛盾——规格 g 的底座定义句自带幻态**。

**[L5-03｜P2] NEEDS_REVIEW→PENDING→再耗尽→再 NEEDS_REVIEW 循环无界；裁决行为零记账；告警重发语义未写**（任务书点名项）。

**[L5-05｜P2] 人工裁决转移未纳入规格 c 条件转换协议**。
规格 c 的 `UPDATE … WHERE status='PENDING_GATEWAY'` 决胜协议只覆盖扫描腿；规格 g 三出口写“→CONFIRMED+事件”无条件谓词。双人并行裁决、或裁决与“重扫后扫描腿即刻回查”竞态时，无 `WHERE status='NEEDS_REVIEW'` 守卫则可能双事件/双转换。修复：一句扩协议（裁决写回同用条件 UPDATE，胜者插事件）。

## 二、规格 h 裁决表完备性

**四分类表本体核验**：成功→条件 UPDATE+胜者事件 / 拒绝→FAILED+事件 / 不可见→留+attempts+1 / 查询失败→同上——后两类有界（达线→NEEDS_REVIEW，经规格 g 闭合）✓；“禁止按 paymentOrderId 裸查归因”封死 L4-02 误归因链 ✓；GatewayResult 错误类别维度+适配器不打平排产在 §4.1 P2 行 ✓（gateway-result.ts:1-5 实测现三字段无类别，L4-03 兑现）。缺口如下。

**[L5-07｜P1] 四分类缺第五类现实——“网关可见但未决（处理中）”与“网关可见但异常终态”无归属行**（任务书点名项）。
推演：①“处理中”（网关明示退款已受理、未终局——回查时点的**常态**而非边角）：四分类中无位。“不可见”行的定义（读延迟/传播中/未创建）是**认知性**不可见（查不到），与网关**明确回答未终局**语义不同；实现者两种归法都“有据”——归“不可见”则行为正确但定义被拉伸，归“明确成功”（部分网关把“已受理”回报为成功类状态）则过早 CONFIRMED。②异常终态（渠道侧到账失败挂起类——既非成功、非拒绝、亦非不可见的**终局**态）：四分类+“明确拒绝 vs 歧义”二维均容纳不下，唯一合理落点是 NEEDS_REVIEW 人工，但表无此行。裁决表是 L4-02“误分类”修复的正身件，缺类即逼实现者即兴——恰是要封死的洞。P1。修复：加两行（处理中→歧义，同不可见处置；异常终态→直接 NEEDS_REVIEW）或明文并类规则一句。

**[L5-08｜P1] 降级键路径在扫描腿的落地未写——gatewayRefundId NULL 行的自动腿行为未定义**（任务书点名项：“人工核对”在自动扫描里怎么落地）。
推演：扫描腿是 @Interval 自动件（§4.1 P1 行 worker 归属已定）；降级键（paymentOrderId+行 id+amount）按规格 h 本身“须人工核对到笔”——即**自动腿不可用此键裁决**。则 NULL 键行在扫描腿怎么办零字，两种缺省读法分岔：读法 A（跳过不选）→行永留 PENDING_GATEWAY、attempts 永不增、永不达线、**无告警**——L4-01 卡死洞原样回归且更隐蔽（降级键成文反而制造“已处置”错觉）；读法 B（计为歧义 attempts+1）→达线 NEEDS_REVIEW→人工用降级键——即任务书所问“降级键路径实际=转 NEEDS_REVIEW 人工”，正确但未写。关键佐证：dev 库存量行带**非空** gatewayRefundId（2026-10-13 实查，REFUND_ALIPAY_…在案），故 dev 验收永不触发此路径——缺文不会被 dev 验收暴露。P1。修复：一句（NULL 键行：扫描腿不发查询、计歧义 attempts+1、达线即 NEEDS_REVIEW，人工裁决用降级键）。

**[L5-09｜P2] attempts 自增的持久化时点未定——回写事务持续失败可绕过毒丸线**。
规格 h 仅对不可见/查询失败两行写 attempts+1；成功/拒绝两行的**查询后条件 UPDATE 若持续失败**（事务回滚连带 attempts 回滚），行永留 PENDING_GATEWAY 且 attempts 不增→无界重查网关——L4-05 明文点名的残余（“回填事务持续失败→无限重试无上限”），v5 未响应，且新毒丸线机制使残余更隐蔽（闭环故事依赖 attempts，而 attempts 可被回滚击败）。修复：认领时先独立提交 attempts+1（或以 lastAttemptAt 退避），裁决写回另事务——一句。
