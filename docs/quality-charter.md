# REICH 代码质量纲领 v1.0

> 2026-10-04 · 用户令："代码要先进，高效，健壮，完善，反过拟合"
> 五条判据适用于本项目一切代码工作（前端/后端/脚本/文档中的代码示例）。
> 与既有宪法的关系：voice-sheet 管文案、ui-redesign-brief 管视觉、CLAUDE.md 管后端工程纪律、本纲领管代码质量总则。冲突时以更具体者为准。

## 五条判据

### 1. 先进——用当前生态的正确做法，不用十年前的野路子
- 正例：ES module 标准、原生 CSS 能力（container queries/`:has()`/OKLCH）、框架惯用法（Nest 的 Guard/Interceptor 管道）
- 反例：eval 拼脚本、字符串拼 HTML 不转义、jQuery 时代的全局函数堆、复制旧 hack 而不问为什么
- 底线：引入任何非惯用法时必须注释理由

### 2. 高效——性能是功能，数字要量化
- 加载：构建产物体积/请求数 vs 改造前要给数字（如 Tailwind CDN 摘除=去掉 100KB+ 运行时编译器）
- 运行：缓存命中/O(n) 习惯（词表匹配用预编译结构不逐条 includes 全文扫）
- 汇报：涉及性能声称必须带实测数字，"感觉快了"不算

### 3. 健壮——失败路径和成功路径一样认真
- 降级真实存在：@supports 包裹、注入失败页面不塌、规则文件读不到 fail-closed 带日志
- 边界：空输入/超长输入/旧数据（无 factCard 的存量商品）都有明确行为，不靠"应该不会发生"
- 错误：错误信息带定位（哪个字段/哪条规则/哪个文件），不抛裸 500

### 4. 完善——验收清单逐项打勾留证，不做"大体过了"
- 每项交付自带证据：测试输出原文/curl 实录/截图路径/复现命令
- 覆盖面：改动影响到的每条路径都验过，包括反路径（401/403/404）
- 台账：挂账项写清"为什么不做+什么时候做"，不静默蒸发
- 构建产物视觉验收纪律（M2 双盲审 P1 教训新增，2026-10-05）：凡涉及 CSS/构建管线的视觉交付，验收必须含 build 产物视觉 diff——仓外 dist + vite preview，关键页在代表视口抽查 computed style 并对比 dev；"只验 dev 未验 build 产物"不算验收（CSS 层叠反转只在 build 产物显形）。

### 5. 反过拟合——修因不修果，禁特判压症状
- 禁止为通过对比/截图/测试而 hack：发现视觉漂移就 `!important` 压住、发现测试红就改断言迁就实现——都是过拟合到基线
- 修复必须能回答"为什么这是正确修法"：根因在层叠规则就在 reset 层补齐，根因在数据形状就在源头修正
- 有意的视觉/行为变化要如实标注为改进，不伪装成"零变化"；无意的变化如实报告为回归
- 单例不立法：一次性现象不提炼成普适规则（触发条件？最硬反例？答不上只记观察）

## 执法方式

- 实施席任务书按本纲领写验收；审计席按本纲领设靶（尤其第 5 条：审计要专找"压症状"式修复）
- 违反第 5 条的修复一律打回重修；违反 1-4 条按严重度 P1/P2 记账

## 双盲审制度（v1.1 新增，用户令 2026-10-04）

里程碑级验收一律双盲审，要求多 agents 下场：

1. **盲抽离**：审计席任务书只含"范围（commit 区间）+维度（纲领五条）"，**不含实施方任何声称**——汇报数字/白名单/"已知差异"一概不给；commit message 中的声称标注为"待验断言，禁止当作锚定事实"。审计席须独立测定后填数字，与断言比对留给协调席。
2. **双席独立**：两席同范围同维度并行，互不知晓对方存在与结论，禁止通信；各自报告独立成文。
3. **协调席比对**：同一发现双席皆中=高置信直接采纳；单席命中=协调席复验裁决；对照原始任务书查两席共漏。
4. **实施侧盲**：实施席不知审计席身份与靶点（agent 隔离天然满足，任务书不得预告审计重点）。
5. **禁串谋**：审计任务书不得引用其他审计席的产出或措辞；协调席汇总前不向任何审计席披露比对结果。
