## 一、方向一：Layout 现代式审美

### 1.1 设计裁决（A 席提出，审查席修正，协调席采纳）

**定调：糖果高级化（Editorial Candy）**——调色盘不动，动排版胆识和色彩用法；从"贴纸感的可爱"升级为"编辑感的可爱"。

三条核心动作（按优先级）：

1. **字体先行**：自托管 Barlow 可变字体（上游 `BarlowGX.ttf` 转 woff2，OFL 协议），hero 标题放大到 `clamp(2.5rem, 8vw, 7rem)`（实施取 2.5rem 下限：375px 屏 7 字不溢出，1440px 命中 7rem=112px），字重 900 与正文 400 拉开阶梯。投入最小、现代感收益最大。v3 任务书"大气靠排版与留白传达"直接为此背书。
2. **色彩系统化**：tokens 改 OKLCH 定义，soft/ink/hover 档全部 `color-mix(in oklch, …)` 自动派生；整区平涂**按 §0.5 预算执行**（营销区块 ≤3 处/页），删装饰性阴影。
3. **商品区破节奏（bento，审查席修正参数）**：均等 3 列改 bento——**主打位为 2×1 横版主打条**（不用 2×2：6 张商品图全是 800×1067 竖版 3:4，进横方格只能裁剪；2×1 横条内嵌 3:4 锁比例，图不裁）；其余 5 件单格群。**选品规则：本期=publishedAt 最新一件；方向二落地后转后台 featured 勾选项**（双轨真实依赖之一，见 §3）。卡片用 container queries 自适应内部排版，`:has()` 整卡 hover 联动；品牌故事区加一处 `@supports` 包裹的 scroll-driven 渐显（Firefox 降级静态，零损失）。

**反趋势（明确不做）**：玻璃拟态、深色模式（糖果色系只在白底成立）、第二条跑马灯、scroll-jacking、3D/WebGL、入场动画全家桶（stagger 只留 hero）、>16px 大圆角卡。

### 1.2 技术裁决（B 席提出，审查席支持，协调席采纳）

**路径 B 为主干（Tailwind 本地构建），清理子集前置；明确不做组件化重构（路径 C）。**

- 定位一句话（消解 v1.0 的 A/B 张力）：**构建为存量，原生为增量**——Tailwind 只管它已经在管的布局（92-94% 工具类的现实载体），container queries/OKLCH/`color-mix()`/`:has()` 等新特性全部走原生 CSS。
- 为什么不把手写化当路线：把三页 91% 工具类逐页重构成语义 CSS=4-6 人日换用户不可见的等价物，与毙掉路径 C 同一把尺。
- 为什么清理必须前置：131 个幽灵变量不清，构建化只是把垃圾从"运行时静默失效"编译成"构建时静默失效"。
- **"成本摊薄"的诚实折扣**（审查席钉正）：仓里有 vite+postcss 配置壳，但 **package.json 无 tailwindcss 依赖**、vite build input 只配了 index 一页、preflight 与 3,689 行 main.css 的层叠冲突调试是真活儿——摊薄的是"引入"成本，摊不薄"调试"成本，已计入 F3 估价。

### 2.3 区块链裁决（审查席攻击成立，协调席全盘修正）

**不做任何公链集成**（代币/NFT/溯源/DID/智能合约全部是戏台，理由见会话记录）。**采用区块链的"链"本体技术：哈希链操作台账——但按诚实定位+外部锚重写。**

- **威胁模型摆正**：能改 SQLite 的人同样能重算哈希链——无锚哈希链对**知情恶意篡改防御为零**。它真实防的是：不知道链存在的手滑改库、绕过管理页的无意编辑、以及"改一条→跑脚本→红灯"的演示仪式。
- **加真锚（+0.5d，采纳审查席方案 a）**：verify 脚本每次运行把最新头哈希追加进 git 跟踪的 `docs/audit-chain-head.txt` 并提交——锚出系统外。此后改库者须同时伪造 git 全部历史提交，防御才真正成立。
- **诚实话术**：禁用"密码学防篡改"。改为——"商品操作台账链式校验：绕过管理页直接改库会被当场抓出；头哈希锚定在 git 历史里，事后改库不留痕是做不到的。"
- **类比钉正**：与 QLDB/证书透明度日志**数据结构相同、信任模型不同**（它们的锚在托管方/第三方，我们的锚在 git 历史）——补锚后类比才成立，引用时须带这句。
- 落点：B4 接线的 audit_logs 表加 `prev_hash` 列；每条商品写操作=内容+前条哈希 SHA-256 链接；verify 脚本离线重算全链+比对 git 锚。

## 三、总体排布与决策点

**双轨排布（删"无相互依赖"伪命题，三处真实依赖已明示）**：
① F7 的 bento 主打位选品规则→方向二 M3 的 featured 勾选位（本期先用 publishedAt 过渡，接口形状预留）；
② M3 的 admin.html 样式体系→等 F3 构建链或纯 CSS 占位（不造体系外孤岛）；
③ M2（refresh）→M3 消费，轨内有序。
除上述外，F 轨与 M 轨可并行。

**总量 22-26 人日**（区间制；评审/返工节奏另计，不做日历时间承诺）。里程碑：
