## 回执吸收（六条精化，全部采纳）

1. **苏黎世复核结论**：登录态反馈差机制确认但量级按口径分——徽章通道 2ms→47ms≈23 倍（超数量级成立，升级双席共中）；toast 通道 1.25 倍（未超）；698ms 属冷态/大袋工况（方向可信，引用须注工况勿与热态混引）
2. **returnUrl 落位条件**（东京）：游客订单引导态 CTA 挂 `?returnUrl=orders.html`（机制现成 auth.js:460+guard）
3. **同批改词纪律**（东京）："去结算"按钮改词与 waitlist 模态文案必须同批落地（避免第四语义）
4. **术语锚同框纪律**（东京）："小本本"等隐喻词只在锚同框句中出现（主句+副句"在个人中心·我的心头好里"同框=合规）；孤立使用即违规回退
5. **反馈分量原则**（东京）：在场对称、分量不对称——取消收藏提示比添加更轻更短（无按钮、时长短）
6. **纽约补全**（并入 A4）：动态 import 修死钮后四页徽章首点前仍不可见——徽章初始渲染同步读 localStorage 必须同批（"否则修完死钮留半个信任残缺"）；页脚去样式时真链接与纯文字须视觉区分；连击/焦点终版表述="同一现象两层：计费层零丢帧（纽约证实）/焦点层每击丢失（苏黎世证实，机制=innerHTML 重渲）"
7. **苏黎世拆分建议**（采纳）：P2-5 的"ESC 重开丢已输入词"半件是行级修复（保留 input 值）提到 B 档前部先做；combobox 键盘导航留尾部
8. **苏黎世保留意见**（采纳）：订单演示数据展开后"当前展示的是演示数据"标签须保持可见——该页唯一值得守住的资产
