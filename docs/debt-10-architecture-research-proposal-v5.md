## 2. 协商记录（v5 增量）

**T9 规格 g（新增——四审 L4-01）**：第四出口 NEEDS_REVIEW。扫描腿 attempts 达上限（毒丸线 3——与 domain_events 腿共用阈值，派生：F 员 C10 毒丸 3 的域内沿用）→ `status='NEEDS_REVIEW'` + 告警（最小落地物=OpenObserve 可查日志行）+ 人工裁决。守卫计入语义：NEEDS_REVIEW **计入保留额**（保守——冻结而非释放，对冲 v4"无限期冻结无人知"缺口的告警半边）。人工裁决出口：确认成功→CONFIRMED+事件 / 确认拒绝→FAILED+事件 / 重扫→回 PENDING_GATEWAY（attempts 清零）。
来源：【四审逻辑路 L4-01 实证 + 执笔人成文】

**T9 规格 h（新增——四审 L4-02）**：回查键形状 + 查询结果四分类裁决表。
- **回查键优先序**：① gatewayRefundId 非 NULL → 按其查（唯一确定本笔）；② gatewayRefundId NULL（崩溃在 gateway.createRefund 调用前）→ 降级键=paymentOrderId + 本表 refund 行 id + amount——网关侧按单对账查询，须人工核对到笔（金额+时序），**禁止**按 paymentOrderId 裸查后直接归因（可命中同单另一笔——四审误归因链封死）
- **查询结果四分类裁决表**：

| 网关查询结果 | 分类 | 处置 |
|------------|------|------|
| 明确成功（退款到账）| 确定 | 条件 UPDATE→CONFIRMED + 胜者插 REFUND_CONFIRMED |
| 明确拒绝（网关回绝/风控拦截）| 确定 | →FAILED + REFUND_FAILED |
| 不可见（读延迟/传播中/未创建）| 歧义 | 留 PENDING_GATEWAY，attempts+1，续扫 |
| 查询自身失败（网络/超时/5xx）| 歧义 | 同上 |

- 配套：策略层返回须带错误类别维度（明确拒绝 vs 歧义）——GatewayResult 扩展 + 适配器不再对 `!success` 一律 throw 打平（现行 strategy-gateway.adapter.ts:131-132 两分支无差别 throw——v4 引 :128-131 修正为 ：128-132 含 throw 行）——排产 §4.1 P2。
来源：【四审逻辑路 L4-02 + 实操路实证 + 执笔人成文】

**T9-e 补全（四审 #9/#10）**：切换 commit 边界=**五处同一 commit**（守卫读源 aggregate:222-224 / 仓储 save:148-160 / 事件 REFUND_* / 迁移脚本（存量转表）/ 过渡期对账腿脚本）。**双轨期写路径归属：切写即切换**——W12 落表与守卫读表同一 P2 批次，无双源并存窗（v4"三处"表述废止——漏迁移脚本）。切换运行时工序次序：停旧写（部署）→迁移存量（'PENDING'→PENDING_GATEWAY 映射成文——交扫描用 gatewayRefundId 回查裁决）→对账核对（两源行数+金额和）→开新写。回归验收腿=typecheck + npm test + test:e2e（仓内现成，指名）。
存量注记：dev 1 行畸形探针数据（主单 0.01<退款 0.05）——转表脚本**只转不验**（守卫切换后回读校验会拒此行）。
