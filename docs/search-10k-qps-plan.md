# 10k QPS 搜索架构方案书

> 2026-10-07 · 多 agent 方案研究（四席独立调研后合并）：架构席/推理席/缓存数据席/演进成本席。
> 命题：从当前栈（NestJS+MeiliSearch v1.54.3 单机+Zinc 备+SQLite+CPU embedding）演进到 10k QPS 搜索服务量级。
> 全部外部数字带来源与检索日期（2026-10-07）；自算数字带假设与公式。四席原文与负面项清单见各章。

## 零、合并裁决与四席共识（先读这章）

### 共识（多席独立得出同一结论）

1. **"埋点第一"**（三席独立呼应）：查询日志是所有容量决策的眼睛——历史无法补采、命中率须实测校准（架构席：命中率<40% 则容量翻倍；缓存席：Zipf 假设须自家 30 天日志验证；演进席：列为第一不可逆决策）。
2. **云 API 终态不可行**（两席独立）：10k QPS ≈ 60 万 RPM / 12M TPM——超 OpenAI 最高配额、无供应商可承诺；且比 GPU 自托管贵 3-27 倍。API 只做溢出通道。
3. **Meilisearch 自托管的真代价是"自建复制管线"**（两席独立）：官方分片/复制是 Enterprise 功能，OSS 路线=多实例+上游双写+自管一致性——读扩展可行，运维负债随规模增长。
4. **CPU 跑 0.6B 级模型不可行**（两席独立）：数千核需求，数学上出局；CPU 只留 bge-small 作降级兜底。

### 分歧裁决

| 分歧 | 架构席 | 缓存席 | 裁决 |
|---|---|---|---|
| 缓存杠杆幅度 | "砍一个量级（÷10）" | 专项计算=**5-7 倍**（Zipf α≈0.75+搜索引擎缓存研究，命中率上限 ~85% 因 15% 查询是新词） | **取缓存席 5-7 倍**（专项计算席胜出；逼近 10 倍需牺牲深翻页+L1 预热叠加） |
| Meili 单实例容量 | 假设 500-1k QPS（标注"最脆弱一格"） | — | 保留为**最高优先级待实测项**（官方无 QPS 锚点，bench 工具自测） |

### 统一推荐（一句话版）

**现在只做三件不可逆的事（埋点/多语言 schema/6 SKU 窗口期锁定 embedding 模型），按流量信号走四阶段（¥2k→¥10k→¥20k→¥50k 月成本），终态=缓存（5-7 倍）+GPU 推理池（TEI+Qwen3-0.6B，2 卡稳态弹性 10 卡）+Meili OSS 读副本 6-8（上游双写）+PG 读写分离，换 ES/Milvus 留作六条可测量判据（D1-D6）触发的分岔而非现在预付。**

## 一、架构章（架构席）

### 关键事实
- Meilisearch 官方 scaling：分片/复制需 **Enterprise Edition**（v1.37+）；OSS 唯一水平扩展=无状态多实例+上游双写+LB 轮询。单索引建议 <2TiB（百万级商品索引 1-2GB，余量 1000 倍——**索引规模不构成换引擎理由**）。
- ES 10k QPS 典型拓扑：单分片 10-50GB、1 副本基线、读吞吐随副本近线性扩展（Elastic 官方博客 2025-12）。
- 大厂分层（淘宝主搜索 2015 公开分享）：索引分层省 300+ 台机器；成熟电商搜索=请求理解→多路召回（倒排/向量/行为）→粗排→精排→重排——**向量召回只是多路之一，可独立熔断**。
- Milvus 2.2 官方基准：12C 单查询节点 10,248 QPS@1M 向量（SIFT/HNSW 口径）。
- 电商查询分布：头部查询占 50-60% 流量、约 15% 为从未出现的新查询（Constructor 2025 等）——缓存命中率天花板 ~85%。
- Embedding 推理差距：CPU 朴素 448 tok/s vs GPU 专用服务数千 tok/s（Infinity 官方基准口径）——两个数量级。

### 终态参考架构（文字版）
```
客户端 → CDN → LB×2（ECMP）
  → NestJS API 无状态×10-12（L1 进程缓存+查询理解）
     ├→ L2 Redis 结果/向量缓存（1主1从→cluster）
     ├→ GPU embedding 池（TEI×2-4+1，CPU int8 降级池）
     └→ 引擎读层：Meili 读副本×6-8（LB 轮询，OSS 上游双写）
         ├→ 降级第一跳：Zinc×2（限流无向量）
         └→ 兜底：PG 只读×2（LIKE+排队）
写路径：商品变更→队列→单写者 indexer×2（HA）→扇出写各副本+版本戳失效
```

### 换引擎分岔判据（D1-D6，测量触发非信仰）
| 判据 | 阈值 | 动作 |
|---|---|---|
| D1 索引大小 | >2TiB | 分域索引→仍超则 ES |
| D2 读副本数 | >8 仍不达标 | Meili Enterprise vs ES 评估 |
| D3 双写复制故障 | lag>5s 或月不一致≥2 次 | 买 Enterprise 或迁 ES |
| D4 相关性能力 | 需 BM25 调权/聚合分析 | ES 评估 |
| D5 向量规模 | >5000 万或混合过滤>10k QPS | 仅向量路迁 Milvus |
| D6 成本 | Enterprise 报价<2 人月/年 | 直接买 |

### 分层实例表（终态）
LB 2 / API 10-12 / Redis 2（→6）/ GPU 2-4+1 / Meili 副本 6-8+1 / Zinc 2 / indexer 2 / PG 只读 2。
**待实测校准项（优先级）**：A6 Meili 单实例 QPS > A4 GPU 短查询吞吐 > A2 NestJS 节点容量。

### 可用性：全栈对等降级
每层定义正常/降级/兜底三态（缓存→仅 L1；embedding→CPU 池→向量路熔断纯关键词；引擎→Zinc→PG LIKE）。任何单层全灭搜索不 404。

## 二、推理章（推理席）

### 模型终裁：Qwen3-Embedding-0.6B
中文 C-MTEB 66.33（BGE-M3 口径 59.56）；MRL 32-1024 维独有；4B 质量增益不值 3-4x 成本；TensorRT 有全零输出坑排除。

### 三路线对比
| 维度 | GPU 自托管（TEI+0.6B fp16） | CPU 集群 | 云 API |
|---|---|---|---|
| 1k QPS | 2 卡 L4/A10 | 200-520 核勉强 | 需企业配额 |
| 10k 峰值 | 弹性 8-10 卡 | 数千核不成立 | 不可承诺 |
| 月成本 | $660-4,300 | >$2,000-10,000 | $2,590-19,440 |
| P99 | 5-20ms | 380ms+（0.6B） | 50-200ms |

**GPU 自托管是唯一同时满足质量/峰值/成本的路线**（锚点：L4 实测 1400 emb/s，TEI token 级动态批）。

### MRL 工程定位（重要澄清）
MRL 是**检索/存储优化非推理优化**：一次推理出 1024 维截 256 维做粗召回（ANN 内存省 4x），forward 成本不变。

### 推荐部署
TEI 1.9 部署 0.6B fp16：`--max-batch-tokens 16384 --max-concurrent-requests 512`，查询统一官方指令前缀，截断 128 token。降级链：GPU 满→API 溢出→bge-small CPU 池。已有 vLLM 栈可换（短序列吞吐高至 2.4x，需压测）。

## 三、缓存与数据章（缓存数据席）

### 多级缓存
L1 进程内（每实例 5 万条结果+2 万条向量，~105MB）→ L2 Redis 主从 8GB（100 万结果+50 万向量，~3GB）→ 回源 singleflight 合并。

### 命中率叠加（诚实计算）
| 情景 | 合并命中率 | 回源 QPS |
|---|---|---|
| 悲观 | 30% | 7,000 |
| 期望 | **80%** | **~2,000** |
| 乐观 | 86% | 1,400 |
**削减 5-7 倍（非一个数量级）**；逼近 10 倍需 L1 预热+只缓存前 3 页+牺牲深翻页。

### 缓存三防
穿透：布隆过滤器（百万词 1.2MB）+负缓存 30-60s；雪崩：TTL 随机抖动+双层错峰；击穿：热词逻辑过期（物理不删异步刷新）+singleflight。

### Redis 不上 Cluster
10k QPS 下实际 ~1.2 万 ops/s=单实例标称的 7%（官方基准 18 万 ops/s）。Cluster 两个触发条件都够不着。

### 一致性：维度版本号（优雅解）
商品改→该类目版本号 INCR→新请求自动拼新 key→旧 key 等 TTL 自然死。失效+重索引共用 WAL→Debezium→Kafka 一条事件总线。价格/库存等强一致字段不进结果缓存（回源实时拼装，列表页陈旧 5-30s 设计值）。

### SQLite→PG 迁移清单（六阶段）
pgloader 全量（**坑：issue #1040 迁移中删数据，须空库演练**）→**SQLite 无 CDC**（Debezium 不支持）增量追平须自研双写/重放（最大工作量格）→灰度切读→分钟级维护窗切写→重灌索引下线 SQLite。PgBouncer transaction 模式+1-2 只读副本。

## 四、演进与成本章（演进成本席）

### 关键事实
- Meilisearch sharding/复制=Cloud/Enterprise 专属，自托管分布式仍在 GitHub issue 阶段。
- OpenAI embedding Tier 5 限额 10M TPM——10k QPS×20token=12M TPM **超限**。
- GPU 性价比主力=A10（包月 ~¥1,366，渠道价）；T4 旧机型反贵。
- 人力是云成本 3-6 倍——"做大"路径上**人先于机器成为大头**。

### 四阶段路线（流量信号触发）
| 阶段 | 触发信号 | 关键动作 | 月云成本 | 人力 |
|---|---|---|---|---|
| P1 ≤100 QPS | CPU>60%/P99>200ms/写争用 | ECS×2+PG+Redis+**埋点** | ¥1.5-3k | 0.5 人 |
| P2 ≤1k | 缓存命中<40%/Meili CPU>70% | Meili 副本×2-3+embedding 切 API/GPU+降级开关 | ¥8-12k | 1 SRE+2-3 后端 |
| P3 ≤5k | 副本 4+ 仍顶不住/需灰度 | ES 云 3 节点+K8s+A10 自托管 embedding | ¥15-25k | 平台组 2-3 人 |
| P4 ≤10k | P99>100ms 常态/大促 10x 不过 | ES 6-10 节点+GPU×2-3+多 AZ | ¥35-70k | 4-6 SRE+5-8 后端+算法 1-2 |

### 不可逆决策表（现在做的三件）
1. **查询埋点**（历史无法补采）——现在。
2. **商品多语言字段 schema**（中/英/日/韩）——SKU 上量前，后补翻译=全量回填。
3. **embedding 模型锁定**（6 SKU 窗口期试错几乎免费；50 万向量后换型=全量重算+双索引灰度）。

### 风险
SPoF 残留：单云（接受）/模型版本（版本化+双索引）/bus factor（P4 前 ≥2 人懂全链）。大促 10x：三层降级阶梯（语义→关键词→缓存热榜）+分级限流+按量弹性；**降级开关 P2 就建并演练**。数据：SQLite 每日快照为 P1 第一动作。

## 五、负面项与未决项汇总（四席合并，如实全露）

1. "Top 10% 词占 80%+流量"无电商直接公开实证（Zipf 通用口径+Meta 转引）——须自家 30 天日志验证。
2. Meili 单实例 QPS 无官方锚点（A6=假设）——bench 自测为落地第一步。
3. TEI 官方 A10 数字未提取（借 Baseten L4 同类锚）；GPU 短查询吞吐未含排队论效应。
4. 50 token/查询、各 TTL/容量阈值均为设计值或假设——埋点后逐项校准。
5. 国内云精确包月价未获官方直出（第三方/旧价已标注）——控制台复核。
6. SQLite→PG 增量追平无现成 CDC——最大自研工作量。
7. 竞品单方数据（Manticore 指控 Meili 内存 15 倍等）采信级别低，仅量级参考。
8. 本方案书所有 QPS/延迟为公开基准或经验量级，**非本业务实测**（当前 6 SKU 无从实测）。
