## 三、罗马陈列师·二次复审（动线 7.5/10）

**对 B4 反转的专业回应（全文要点）**：四席理由逐条判定全部成立+自己复测更深缺口——**同款二次加购走 updateItemQuantity 合并路径只 notify quantityUpdated（cart.js:203），不触发 itemAdded——面板不自开脉冲不响（实测 overlay display:none）——"我的方案不仅打断浏览，在第二次拿同一件时连确认都没兑现"**。结论："裁决正确，我服。陈列师为顾客动线服务：她的逛比我的戏剧重要。"

**买 B1 施工三条成败条件（动线权威技术补刀）**：
1. **事件双挂是生死线**：toast 只挂 itemAdded 则同款二次加购零反馈（最高频场景静默）——必须 itemAdded+quantityUpdated 双挂，或合并路径改发带 merged 标记的 itemAdded
2. toast 停留 ≥5s 且 hover 暂停（移动端单手 4s 不够）；"去结算"ink 底主钮/"继续逛"文字钮——双选不是双主语；**toast 的"去结算"语义=打开购物袋面板**（与"抽屉留主动点击"自洽），面板内结算钮才给诚实提示，别让 toast 直接撞"未开通"死胡同
3. fly-to-cart ≤400ms 别抢 toast 注目；reduced-motion 兜底背书

**对 C5 勾选砍除表态**：接受且是更高一层解（"我上轮让半个 UI 说整句话，东京做的是这句话不该说——**拆除优于修补**"）；两落点：①"共 N 件"必须继承件数求和语义（productQuantity，别回退按行数）②"清空"整袋确认式对但确认文案用品牌声音

**上轮复核**：9 项中 7 项干净落地/1 半落地（意 B4 合并路径缺口）/1 欠规格尾数（C24 实 input 13px<规格 16px——**16px 规则写在不存在的 .cart-item-select（"修错房间"第二例）**，C5 落地时随模型消解）

**A1 PDP 动线规格四条**：①整卡热区可点（图+标题为链接），**.btn-bag 与心形必须 stopPropagation——今天心形已 stop（wishlist.js:34）bag 钮没有**；②**逛的连续性**：PDP 返回回列表原滚动位（history.scrollRestoration 校验+锚点兜底）——"逛到第七张卡进去看一只包，回来不该从橱窗顶重来"；③PDP 内反馈同语言（同 toast 双选+fly-to-cart 飞向页头袋钮；PDP 不自动跳结算）；④规格三行放图右价上（"摸得着的答案放在钱旁边"）

**买 B4 心愿单**：支持（"认脸→心头好（她的房间）→复购"同一条回头客动线；动作在原地资产在房间）；**B6 信任行**：位置=总价行下方结算钮上方（"最后一眼犹豫的位置"）12px ink-faint 别抢结算钮；**B13**：两处入口一个落点（footer+信任行可点入），不进主导航（"门面不摆法律文书"）

**增量 P1×2（实测）**：
- **P1-1 同款二次加购零反馈**（结构缺口=意 B4 自首=买 B1 前置条件）
- **P1-2 心形 pill 误带全套加购契约（地雷）**：home-products.js:96 heartButton 携带 data-add-to-cart=true+sku/name/price/pic 全套（bag 钮复制残留），现靠 rebindWishlist→stopPropagation **侥幸屏蔽**——心形自己的 data-* 无人消费；时序一变心形点击即入袋；**与 A1 卡片可点化同批拆除（只留 data-product-id）——这是拆雷唯一窗口（卡片事件结构反正要动）**
